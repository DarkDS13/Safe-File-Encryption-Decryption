How this works

  1. Your passphrase stays here. The key is derived in your browser with Argon2id and is never sent to the server.
  2. Files are encrypted before they leave. AES-256-GCM, in 1 MiB segments, each with its own authentication tag.
  3. The server stores sealed containers. It cannot read them, and neither can an administrator.
  4. There is no recovery. Lose the passphrase and the file is gone for good. That is the design, not an oversight.

What is actually being used, and why
AES-256-GCM
An authenticated cipher. As well as hiding the contents it produces a tag over each segment, so any alteration to the file is detected rather than silently decrypted into rubbish.
Argon2id
Turns your passphrase into a 256-bit key. It is deliberately slow and memory-hungry (64 MiB, 3 passes) so that guessing passphrases in bulk is expensive.
1 MiB segments
The file is encrypted a segment at a time so memory use stays flat whether the file is 10 KB or 50 MB.
SHA-256
Recorded before encryption and checked after decryption, proving the file came back byte for byte.
